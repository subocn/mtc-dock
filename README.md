# mtc-dock

能对接充电桩的电摩充电机，在 `mtc-link` 之上的交出判定。

本仓先私有。与 `mtc-link`、`mtc-solo` 一起稳定后再公开。公开文本不出现公司、客户、供应商、价格、料号和具体机型。

## 用途

充电机一边用 `mtc-link` 和 BMS 说话，另一边才把电池数据交给桩侧。本仓规定什么条件下这批数据可以交出。桩自己的报文、导引和连接器不在这里。

一台机器只符合 `mtc-solo` 或 `mtc-dock` 其中一份。符合本仓的机器，电池侧电流仍由 `mtc-link` 的 `0x01` 决定；本仓额外卡住朝向桩的那一次交接。

## 本仓包含

- 可以交出的字段只有这些：请求电压、请求电流，以及 `0x04` 里的荷电、温度、容量、额定电压、化学体系和允许值。
- 下列任一成立时，这些字段不交给桩侧，充电机也不进入桩侧能量传输：
  - 电气匹配没有通过；
  - 选用的加密套件没有核对通过，或解包失败；
  - `0x04` 的有效位为 0；
  - 超过 3 秒没有新的合法 `0x04`；
  - 选用令牌时，最近一帧 `0x04` 没有被该令牌覆盖。
- 字段交出之后，桩侧超时和结束条件由桩侧自己的规则执行。BMS 口的超时仍按 `mtc-link` 与本机所符合的出流规则，两套超时不混用。
- 目录里记录所依赖的 `mtc-link` 版本。

## 本仓不包含

- 不写桩侧报文，不写枪、导引、接触器和硬件。
- 不声明通过某项充电桩国家标准。产品里的桩侧栈按该标准自行实现，不从 `mtc-pile-sim` 抄模拟器代码。
- 不把 BMS 接到桩侧那根线上。桩侧信号止于充电机。
- 不改 `0x01` 到 `0x04` 的字节，也不把 `0x04` 用作抬高输出电流的依据。
- 不写不对接充电桩时的满 1 秒判定。那是 `mtc-solo`。

## 依赖

只依赖 `mtc-link`。`mtc-pile-sim` 依赖本仓，本仓不依赖 `mtc-pile-sim`。

## 现状

仓还没从工作仓拆出。交出条件按通信规范里「面向桩时 `0x04` 失效则不进入桩侧能量传输」写成独立判定，不把桩侧组帧带进来。

# mtc-dock

作者：苏勃(subo)

许可：Apache-2.0，全文见仓库根目录 `LICENSE`。仓库仍先私有。公开时这份许可证随仓库分发。

能对接充电桩的电摩充电机，在 `mtc-link` 之上的交出判定。

本仓先私有。与 `mtc-link`、`mtc-solo` 一起稳定后再公开。公开文本不出现公司、客户、供应商、价格、具体料号和具体机型。

## 用途

充电机一边用 `mtc-link` 和 BMS 说话，另一边才把电池数据交给桩侧。本仓规定什么条件下这批数据可以交出。桩自己的报文、导引和连接器不在这里。

一台机器只符合 `mtc-solo` 或 `mtc-dock` 其中一份。符合本仓的机器，电池侧电流仍由 `mtc-link` 的 `0x01` 决定；本仓额外卡住朝向桩的那一次交接。

## 本仓包含

- 可以交出的字段是 `0x01` 的请求电压、请求电流，以及 `0x04` 的 28 字节：荷电、包实测电压、最高和最低单体电压及其序号、最高和最低温度及其传感器序号、额定容量、额定电压、化学体系、允许电压、允许电流、允许温度、剩余时间，以及绝缘、连接器、单体过压、单体欠压、过温和低温。过温和低温不写入桩侧 BSM 字节 6。车架号、软件版本、厂家、序列号、生产日期和循环次数不在 `0x04` 里，保持 0。模拟器短装不保存包实测电压和四个序号，BCS 短装不写剩余时间；产品按标准第 11 章组帧。
- 下列任一成立时，这些字段不交给桩侧，充电机也不进入桩侧能量传输：
  - 电气匹配没有通过；
  - 选用的加密套件没有核对通过，或解包失败；
  - `0x04` 的有效位为 0；
  - 超过 3 秒没有新的合法 `0x04`；
  - 选用令牌时，最近一帧 `0x04` 没有被该令牌覆盖。
- 字段交出之后，桩侧超时和结束条件由桩侧自己的规则执行。BMS 口的超时仍按 `mtc-link` 与本机所符合的出流规则，两套超时不混用。
- 所依赖的 `mtc-link` 版本是 0.1.0。

## 本仓不包含

- 不写桩侧报文，不写枪、导引、接触器和硬件。
- 不声明通过某项充电桩国家标准。产品里的桩侧栈按该标准自行实现，不从 `mtc-pile-sim` 抄模拟器代码。
- 不把 BMS 接到桩侧那根线上。桩侧信号止于充电机。
- 不改 `0x01` 到 `0x04` 的字节，也不把 `0x04` 用作抬高输出电流的依据。
- 不写不对接充电桩时的满 1 秒判定。那是 `mtc-solo`。

## 依赖

只依赖 `mtc-link`。`mtc-pile-sim` 依赖本仓，本仓不依赖 `mtc-pile-sim`。

## 出流剖面

本仓是对接剖面，只规定电池字段能否交给桩侧。BMS 口的超时仍用 `mtc-link` 的链路剖面：不满 1 秒不停，到 1.2 秒输出为 0。家充剖面在 `mtc-solo`：满 1 秒没有合法 `0x01`，输出已经是 0。桩侧超时不改 BMS 口。三个仓的当前版本是 0.1.0。

## 现状

交出条件写在 `doc/handoff.md`。本仓没有组帧代码。桩侧模拟器在 `mtc-pile-sim`。
